# AgentOps 追赶路线图

> 基于竞品深度扫描 (CMPAAA-251) 的差距分析，按优先级输出可执行的功能追赶清单。
> 生成日期：2026-05-28

---

## 战略定位

**桌面端轻量级 Agent 编排工具** — 作为 Multica/Paperclip 的「单机版替代」，主打：
- 零外部依赖（SQLite + Electron）
- 开箱即用的本地 Agent 管理
- 轻量但功能完整

---

## P0 — 核心竞争力补全 (v0.2)

> 目标：从「能用」到「值得用」。不补这些，产品没有存在的理由。

### P0-1: 多 Agent 并行编排引擎
- **当前**：单 agent 串行执行，无并行能力
- **目标**：支持 N 个 agent 同时执行任务，独立生命周期
- **实现要点**：
  - 进程池管理：spawn/kill/restart per agent
  - 任务队列：pending → assigned → running → completed/failed
  - 实时状态推送：WebSocket 或 IPC event
- **工作量**：3-5 人天
- **依赖**：无
- **对应差距**：多 Agent 并行编排 (差距 -3.7)

### P0-2: Agent 间通信 / 结果接力
- **当前**：agent 之间完全隔离，无通信机制
- **目标**：agent 可以将输出传递给下游 agent，支持简单 pipeline
- **实现要点**：
  - 结果存储：task_logs 扩展为结构化 output
  - 接力机制：task 完成时触发下游 task
  - 上下文传递：agent 可读取前序 agent 的输出
- **工作量**：2-3 人天
- **依赖**：P0-1
- **对应差距**：Agent 间通信/结果接力 (差距 -3.3)

### P0-3: 可视化 Dashboard
- **当前**：renderer 层极简，无监控视图
- **目标**：实时展示所有 agent 状态、任务进度、错误日志
- **实现要点**：
  - Agent 状态卡片（idle/running/error/offline）
  - 任务进度看板（pending/running/done/failed）
  - 实时日志流
  - 错误高亮与恢复按钮
- **工作量**：3-4 人天
- **依赖**：P0-1（需要实时状态数据）
- **对应差距**：Dashboard/可视化监控 (差距 -3.0)

### P0-4: 自动调度 / Cron
- **当前**：所有任务手动创建，无自动化
- **目标**：支持定时触发 agent 执行任务
- **实现要点**：
  - Cron 表达式解析器
  - 调度器：定时检查并触发任务
  - 任务模板：预定义重复任务
- **工作量**：2-3 人天
- **依赖**：P0-1
- **对应差距**：自动调度/Cron/Autopilot (差距 -3.3)

## P1 — 企业级能力 (v0.3)

> 目标：从「值得用」到「能用于团队」。

### P1-1: 成本控制 / 预算管理
- **当前**：无任何成本追踪
- **目标**：每个 agent 有月度预算，超限自动停止
- **实现要点**：
  - Agent 预算字段：monthly_limit, current_spend
  - Token 计费集成：按 API 调用计费
  - 超限策略：pause / warn / stop
  - 成本报表：按 agent / goal / 时间段
- **工作量**：3-4 人天
- **依赖**：P0-1
- **对应差距**：成本控制/预算管理 (差距 -2.7)

### P1-2: Squad / 团队编组
- **当前**：agent 平铺，无分组
- **目标**：将 agent 分组为 Squad，支持批量调度
- **实现要点**：
  - Squad 数据模型：id, name, members[], leader_id
  - Squad 级任务分配：leader 自动分发
  - Squad 状态汇总
- **工作量**：2-3 人天
- **依赖**：P0-1
- **对应差距**：Squad/团队编组 (差距 -3.3)

### P1-3: 插件系统 / 自定义 Agent 适配器
- **当前**：5 种硬编码 agent_type
- **目标**：支持自定义 agent 适配器，用户可注册新 agent 类型
- **实现要点**：
  - Adapter 接口定义：spawn, kill, health_check, execute
  - 适配器注册表
  - 配置驱动：JSON/YAML 定义新 agent
- **工作量**：3-5 人天
- **依赖**：无
- **对应差距**：可扩展性 (差距 -3.0)

### P1-4: 技能复用系统
- **当前**：无技能概念
- **目标**：agent 的成功经验可保存为技能，供其他 agent 调用
- **实现要点**：
  - Skill 数据模型：name, description, content, tags
  - Skill 存储：SQLite 扩展
  - Skill 注入：agent 启动时加载相关技能
- **工作量**：2-3 人天
- **依赖**：P0-2
- **对应差距**：技能复用系统 (差距 -3.3)

## P2 — 差异化特性 (v0.4-v0.5)

> 目标：从「能用于团队」到「有独特价值」。

### P2-1: Goal Alignment 机制
- **当前**：goals 表存在但无对齐逻辑
- **目标**：每个 task 自动关联到 goal，agent 了解全局目标
- **实现要点**：
  - Goal 分解：goal → tasks 自动生成
  - 进度追踪：goal 完成度 = tasks 完成率
  - Agent 上下文注入：启动时传递 goal 信息
- **工作量**：2-3 人天
- **依赖**：P0-2
- **对应差距**：Goal/Mission 对齐与追踪 (差距 -1.3)

### P2-2: 多租户 / 数据隔离
- **当前**：单实例单用户
- **目标**：支持多个独立工作空间
- **实现要点**：
  - Workspace 数据模型
  - 数据隔离：per-workspace SQLite 或 schema 隔离
  - 切换机制
- **工作量**：4-5 人天
- **依赖**：无
- **对应差距**：多租户/数据隔离 (差距 -3.3)

### P2-3: Agent 能力评估框架
- **当前**：无评估机制
- **目标**：量化评估 agent 在特定任务上的表现
- **实现要点**：
  - 评估任务集定义
  - 评分机制：正确率、效率、成本
  - 评估报告
- **工作量**：3-4 人天
- **依赖**：P0-1, P1-1
- **对应差距**：Agent 能力评估 (差距 -2.7)

### P2-4: 国际化 (i18n)
- **当前**：无
- **目标**：支持中英文界面
- **实现要点**：
  - i18n 框架集成（vue-i18n 或自研）
  - 翻译文件
  - 语言切换
- **工作量**：2-3 人天
- **依赖**：无
- **对应差距**：国际化 (差距 -2.7)

## 关键依赖关系图

```
P0-1 (并行编排) ──┬──→ P0-2 (通信) ──→ P1-4 (技能) ──→ P2-1 (Goal对齐)
                  ├──→ P0-3 (Dashboard)
                  ├──→ P0-4 (Cron)
                  ├──→ P1-1 (成本) ──→ P2-3 (评估)
                  └──→ P1-2 (Squad)

P1-3 (插件) ──→ 独立
P2-2 (多租户) ──→ 独立
P2-4 (i18n) ──→ 独立
```

**P0-1 是整个路线图的基石。** 没有并行编排引擎，后续所有功能都没有意义。

---

## 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| 并行编排引入进程管理复杂度 | 高 | 高 | 先做进程池，不做协程；用 Electron 的 child_process |
| Dashboard 性能瓶颈 | 中 | 中 | 虚拟列表 + 增量更新 |
| 插件系统过度设计 | 中 | 高 | 先做硬编码 adapter 接口，验证后再抽象 |
| SQLite 并发写入冲突 | 中 | 中 | WAL 模式 + 写队列 |

---

> 追赶不是目的，找到自己的生态位才是。AgentOps 的机会在「轻量桌面端」——当 Multica 和 Paperclip 在云端厮杀时，做一个好用的本地工具。
